# 安全逻辑：默认停机 + 失联阈值 500 ms（代码 + 说明）

> 完整可编译代码见 `safety_logic/safety_logic.ino`，可直接烧录 ESP32，也可导入 Wokwi。

## 1 三条硬规则

1. **上电默认停机**：`state=STOP`，`STBY=LOW`（TB6612 待机），`PWM=0`。只有收到 `cmd=1 (RUN)` 且 CRC/序号合法才驱动；任何复位、烧录后都不自动运行。
2. **失联 500 ms 停机**：`state=RUN` 时，自最后一次**有效指令帧**起 `millis()-lastCmdMs > 500 ms` → 进入 `FAULT`：`STBY=LOW`、`PWM=0`、故障锁存，遥测 flags bit0=1。必须收到 `cmd=2 (CLR_FAULT)` 再发 `cmd=1 (RUN)` 才能恢复。
3. **硬件急停优先**：5A 自锁开关直接切断 12V 动力回路；软件检测 GPIO32 低电平（内部上拉）作为第二路急停输入，任一触发立即 FAULT（flags bit2）。

## 2 为什么阈值是 500 ms

| 依据       | 推导                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 心跳周期     | 上位机每 **100 ms**（10 Hz）发一帧（任务①定稿），500 ms = **5 个心跳周期**                                                                                                   |
| 抗抖动      | 允许连续丢 2 帧 + 串口/Python 调度抖动仍不停机；200 ms 仅 2 个周期，PC 偶尔卡顿就会误停                                                                                               |
| 失控距离     | 限速 70% 后最高车速 `v≈0.183 m/s`，500 ms 内最多前进 **9.2 cm**；车架 200×100 mm，在台架上可接受的失控范围                                                                           |
| 与系统文档的关系 | 系统说明 §十二写"通信中断 200 ms 内将 PWM 置零"：本设计把**判定窗口**设为 500 ms（抗抖），但**判定后归零 ≤10 ms**（控制环周期），归零动作远快于 200 ms。若指导老师要求严格按 200 ms，只需把 `CMD_TIMEOUT_MS` 改为 200，其余逻辑不变 |
| 更长阈值为何不行 | 1000 ms 时失控距离 ≈18 cm，接近车长两倍，在磁吸台架边缘有碰撞风险                                                                                                                |

## 3 状态机

| 状态           | 进入条件                                      | 输出                      | 退出                                    |
| ------------ | ----------------------------------------- | ----------------------- | ------------------------------------- |
| `STOP`（上电默认） | 上电 / `cmd=0` / CLR 后                      | PWM=0，STBY=LOW，绿灯灭      | 合法 `cmd=1` → RUN                      |
| `RUN`        | 合法 RUN 帧                                  | PWM≤179，STBY=HIGH，绿灯亮   | STOP 指令 / 超时 / 急停 / 堵转 → FAULT        |
| `FAULT`      | 超时(bit0) / 超速(bit1) / 急停(bit2) / 堵转(bit3) | PWM=0，STBY=LOW，红灯亮，故障锁存 | 仅 `cmd=2` 清除故障 → STOP，再 `cmd=1` → RUN |

## 4 代码要点（完整版见 `safety_logic/safety_logic.ino`）

```cpp
const uint32_t CMD_TIMEOUT_MS = 500;   // 失联阈值，5×100ms 心跳
const uint32_t CONTROL_MS      = 10;   // 控制环，超时后 ≤10ms 归零
const int      PWM_LIMIT       = 179;  // 70% 占空比（任务④）

void enterFault(uint8_t bit) {
  state = ST_FAULT;  flags |= bit;  applyOutput(0, 0);   // STBY=LOW, PWM=0
}

void loop() {
  // 1) 非阻塞收帧：CRC + 序号合法才刷新 lastCmdMs
  // 2) 急停输入检测（GPIO32 低有效）
  // 3) 10ms 控制环：
  if (state == ST_RUN && (uint32_t)(now - lastCmdMs) > CMD_TIMEOUT_MS)
      enterFault(BIT_TIMEOUT);
  // 有 PWM 但 300ms 内 |Δcnt| < 4 → enterFault(BIT_STALL)
  // 4) 50ms 遥测：#T,... 上报 state / flags / cnt / pwm
}
```

关键实现纪律：

- `lastCmdMs` **只在 CRC 与序号都合法时刷新**；CRC 错帧不得"续命"。
- 用 `millis()`/`micros()` 非阻塞调度，控制环内**禁止 `delay()`**。
- `applyOutput()` 是唯一改 PWM/STBY 的入口，STOP/FAULT 时强制 0，避免多处逻辑漏关。
- 故障锁存：即使心跳恢复，若不发 `CLR_FAULT` 也不得自行回 RUN（防止上位机"假活着"）。

## 6 Arduino-ESP32 2.x / 3.x 兼容说明（Wokwi 编译报错必读）

Wokwi 网页版当前使用 **Arduino-ESP32 3.x** 内核。3.x 删除了旧版 LEDC API：`ledcSetup()` / `ledcAttachPin()` 不再存在，`ledcWrite()` 的第一个参数也从"通道号"改为"引脚号"，直接沿用 2.x 写法会报 `'ledcSetup' was not declared in this scope`（编译失败）。

`safety_logic.ino` 已在文件开头加入兼容层：`pwmSetup(pin, ch)` / `pwmWrite(ch, duty)` 两个包装函数。**默认走 3.x API**（`ledcAttach(pin,20000,8) + ledcWrite(pin,duty)`），只有明确识别到 2.x 内核（`ESP_ARDUINO_VERSION_MAJOR < 3`）或手工定义 `PWM_USE_LEGACY_LEDC` 时才回退旧 API（`ledcSetup + ledcAttachPin + ledcWrite(通道,duty)`）。这样即使内核没定义版本宏，也不会误走旧分支。

业务逻辑（含 `applyOutput()`）无需改动。**如果编译时仍看到旧函数名，按以下顺序排查**：

1. **确认粘贴的是最新版**：在 Wokwi 的 `sketch.ino` 里搜索 `pwmSetup`——搜得到才是新固件；搜不到说明粘贴的是旧版本，重新完整复制 `safety_logic/safety_logic.ino` 覆盖。
2. **确认改的是 sketch.ino 而不是 diagram.json**：Wokwi 有两个标签页，代码只能贴在 `sketch.ino`。
3. **刷新浏览器缓存**：Wokwi 可能缓存了旧 sketch，按 Ctrl+F5 硬刷新后重新粘贴。
4. **确认是新项目**：若用的是旧项目链接，可能保留了旧代码，建议从 <https://wokwi.com/projects/new/esp32> 新建后重贴。
5. **检查是否粘贴完整**：固件共 **256 行**，最后一行是单个 `}`。若 Wokwi 编辑器里行数明显少于 256，或报错是 `expected '}' at end of input`（文件末尾缺右括号），说明复制时被截断了——**不要从聊天预览面板复制**，改用记事本/VS Code 打开 `safety_logic.ino`，`Ctrl+A` 全选 → `Ctrl+C`，再到 Wokwi 的 `sketch.ino` 里 `Ctrl+A` → `Ctrl+V` 覆盖。也可以直接把 `.ino` 文件拖进 Wokwi 编辑器导入。
6. 完成 1–5 后若仍报错，**把新的报错文字/截图发出来**——报错若是别的函数或行号，说明是另一个问题，需要按新报错定位。
